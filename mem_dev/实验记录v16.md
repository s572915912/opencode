## 二、V14：Type-Aware Probe Injection

### 改动

在 eval 脚本的 `_build_probe()` 中，按问题类型注入不同的 PK 段落：

```python
_QTYPE_SECTIONS = {
    "information_extraction":  ["Value Registry", "Technical Specifications"],
    "knowledge_update":        ["Value Registry", "Technical Specifications", "Contradiction"],
    "temporal_reasoning":      ["Chronological Event Log", "Value Registry"],
    "preference_following":    ["User Preferences", "Causal Decisions"],
    "summarization":           ["Narrative Summary", "Chronological Event Log"],
    "contradiction_resolution":["Contradiction", "Value Registry"],
    "event_ordering":          [],  # 用 episodes.jsonl
    "abstention":              [],  # 不注入，避免幻觉
}
```

### 原理

原版把整个 memory.md 塞进 probe，模型容易被无关内容干扰。按题型只注入相关段落，减少噪声。

灵感来自 xMemory 的 top-down retrieval。

## 三、V15/V15a：Theme-Structured SK + Recall 工具

### 改动 1：SK 按主题聚类（V15）

原版把 `knowledge.jsonl` 的 SK 条目全部平铺塞进 compaction prompt。

V15 改为 `clusterSK()` 按关键词聚类成主题组，`formatExpanded()` 按主题结构化输出：

```
### Translation / Service / Port
- [FACT] deepl_api_port: 8080
- [UPDATE] service_port: 3001 (was: 3000)

### Sprint / Review / Date
- [EVENT] sprint review completed | order:12
```

**文件**：`compaction.ts` — 新增 `clusterSK()`、`formatExpanded()`、`writeThemes()`

### 改动 2：Recall 工具（V15a）

新增 `memory_recall.ts`，LLM 可调用 `recall("topic_name")` 按需加载 `.opencode/knowledge/` 目录下的主题详细内容。

模仿 Skills 的分层渐进加载模式。在 BEAM eval 中未被触发（eval 不走 tool-use 流程），分数提升全来自主题聚类。

**文件**：新增 `tool/memory_recall.ts` + `registry.ts` 注册

### 改动 3：死代码清理（V15b）

移除 6 个未使用的函数/常量：`relevantThemes()`、`formatThemeIndex()`、`filterSK()`、`VALUE_RE`、`DATE_RE`、`VERSION_RE`。

无行为变更。

## 四、V16：多存储架构

### 核心问题

所有信息经过 compaction LLM 有损压缩后存入单一 `memory.md`。每轮 compaction 重写整个文件，之前保留的信息可能丢失。

**根因分析**：5 个最弱指标各有不同的信息需求，一个通用 summary 无法满足。

### 改动 1：Append-Only Event Ledger

**文件**：`compaction.ts` — 新增 `extractEventsFromPK()`

每轮 compaction 后，从 PK 的 `Chronological Event Log` 段解析事件，追加到 `.opencode/events.jsonl`。

```jsonl
{"seq":1,"event":"User started with OpenCV 4.7.0 + Python 3.10 + YOLOv5 webcam issues"}
{"seq":2,"event":"Discussion established that OpenCV DNN should load YOLOv5 via ONNX"}
{"seq":3,"event":"Performance monitoring added to stay under 250ms/frame"}
```

**特性**：
- Append-Only：只追加，永不删除、永不重写
- 去重：基于 event text 的 Set 去重
- 7 轮 compaction 后累计 52-70 个事件

### 改动 2：Contradiction Pairs Store

**文件**：`compaction.ts` — 新增 `extractContradictionsFromPK()`

从 PK 的 `Contradiction & Update Log` 段解析矛盾对，追加到 `.opencode/contradictions.jsonl`。

```jsonl
{"topic":"as_14mb","said":"as 14MB","then":"later updated to 14.2MB"}
```

### 改动 3：Read-Side Injection（eval 脚本）

**文件**：`beam_opencode_eval.py`

- `_read_events_ledger()`：读取 events.jsonl
- `_read_contradictions()`：读取 contradictions.jsonl
- `_build_probe()` 修改：
  - `event_ordering` 题：优先注入 events.jsonl + "这是 GROUND TRUTH 顺序"
  - `contradiction_resolution` 题：注入矛盾对 + "你必须说明存在矛盾信息"

## 五、确定性 Rubric Scorer

### 问题

旧 scorer 每个 rubric item 都调 LLM judge 打分（0/0.5/1.0），同一份结果重跑两次可能差 ±15pp。

### 解决方案

分析 324 个 rubric items，发现 86% 是 `"should contain/mention/state: X"` 格式，可用确定性规则匹配。

**文件**：`beam_rubric_scorer.py` — 重写 `score_rubric()`

| 模式 | 覆盖率 | 方法 |
|:---|:---:|:---|
| `should contain/mention/state: X` | 86% | token overlap 匹配（≥0.8→1.0, ≥0.4→0.5, <0.4→0.0）|
| `should not contain: X` | 0.3% | 反向子串检查 |
| `should include: X` | 5% | token overlap（宽松阈值）|
| 弃权模式（`no information`） | 6% | 21 种弃权信号模式匹配 |
| `ask for clarification` | 2.5% | 7 种澄清信号模式 |
| 复杂/其他 | ~8% | LLM judge 兜底 |

### 稳定性验证

```
V16 Run1 vs Run2：所有 10 个指标 Δ = 0.0 ✅
```

### 同时修复 event_ordering scorer

原 `score_event_ordering()` 用 LLM 提取两个 list → substring 匹配，不稳定（同一 run 两题分别 tau=0 和 tau=1）。

改为 LLM 直接输出 rank pairs `[[exp_pos, model_pos], ...]` + semantic prompt，消除 substring 配对失败。

## 七、分析

### 为什么 V16 总分反而低？

1. **API 中断**：Q7 返回空，直接让 info_extraction 从 100% 掉到 50%
2. **compaction 随机性**：每次 compaction LLM 可能保留不同细节，导致单 case 波动 ±10-15pp
3. 真正的代码导致的变化只有 contradiction_resolution +50pp

### 确定性 Scorer vs LLM Scorer 对比

| 版本 | LLM Scorer | 确定性 Scorer | 差距 |
|:---|:---:|:---:|:---:|
| V14 | 65.9% | 51.2% | -14.7pp |
| V15a | 70.9% | 48.2% | -22.7pp |
| V16 | — | 42.3% | — |

LLM Scorer 系统性偏高约 15-20pp，而且不稳定。确定性 Scorer 更严格但完全可复现。
