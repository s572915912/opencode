| **官方评分** | BEAM Nugget Evaluation (GPT-5.4 judge, per-nugget scoring) |

## 修改内容

在 compaction prompt 中新增以下规则：

1. **数值保留**：精确保留所有数字、日期、版本号、百分比
2. **标识符保留**：保留文件路径、UUID、API key 名称、端口号
3. **用户偏好**：保留用户明确表达的偏好和约束
4. **模板新增**：增加 "Key Facts & Values" 结构化输出段

## 问题与观察

### ✅ 强项（官方 Nugget）
- **instruction_following**: 88.3% — 技术指令执行能力强
- **knowledge_update**: 80.0% — 数值/日期/版本号保留效果显著
- **information_extraction**: 70.0% — 标识符精确保留
- **preference_following**: 65.0% — 用户偏好保留良好

### ❌ 弱项（官方 Nugget）
- **summarization**: 0.0% — 官方评分极其严格，需要逐细节匹配
- **event_ordering**: 5.1% — 压缩彻底丢失时序信息
- **contradiction_resolution**: 27.5% — 无法识别对话中矛盾信息
- **multi_session_reasoning**: 30.0% — 跨会话推理仍弱

### ⚠️ 稳定性问题
- 1M Case 2 初次因 compaction 超时（180s）失败 → 增加到 300s 后成功完成（✅ 已解决）
- 500K Case 2 首次运行有 9/20 空响应 → 重跑后仍有 5/20 空响应（API 间歇性不稳定）
- changyou API 在凌晨有一段时间完全不可用（后恢复）

## 方法论说明

1. **消息注入**：只注入 user 消息（`noReply=true`），assistant 消息仅用于计算 token 阈值
2. **压缩触发**：累计 token > 128K 时调用 OpenCode `/summarize` 端点
3. **探测评分**：压缩完成后发送 BEAM 探测问题，模型基于压缩后上下文回答
4. **随机前缀**：探测问题添加随机前缀，防止 API 层面缓存命中导致得分虚高
5. **评测公平性**：所有实验使用相同的注入方式和评分标准
