# RAG V5 阶段总结

## 一、版本定位

RAG V5 是在前序 RAG 消融实验与 500K/1M 深水区压测基础上的一次继续收敛。相比前几个版本主要围绕检索策略、时序重排和融合思路展开验证，V5 的重点不再只是“继续比较哪种召回器更强”，而是把长对话中的分散信息前置整理成结构化记忆，再按题型选择不同记忆片段参与回答。

从路线定位上看，V5 可以概括为：**从检索驱动回答，推进到结构化记忆优先、混合检索补证的题型感知 RAG**。这意味着系统不再单纯依赖 Top-K chunk 临时拼接上下文，而是尝试先沉淀一份可复查、可路由、可复用的 case 级记忆视图，再在记忆不足时回到原始检索证据。

## 二、当前方案概述

结合 `beam_rag_eval_5.py` 的实现，V5 当前方案主要包含以下几层：

### 1. 检索底座保持延续

V5 没有推翻前代已经验证有效的混合检索框架，而是继续保留：

- `Chroma` 向量检索
- `BM25` 稀疏检索
- `RRF` 融合排序

这一层仍然承担“从原始长对话中快速找回局部证据”的作用，是整个方案的底层兜底能力。

### 2. 新增结构化记忆层

V5 最关键的增量，是在检索层之前增加了一层结构化记忆构建流程。具体做法是先将多 session 对话展平并按时序切块，再对每个 chunk 调用本地 OpenCode 接口抽取结构化信息，最后聚合为 case 级记忆。

当前会落盘的记忆文件包括：

- `memory.md`
- `episodes.jsonl`
- `timeline.jsonl`
- `memory.json`

这些文件对应的内容不只是普通摘要，而是尽量把长对话中的不同信息类型拆开存储，包括：

- 叙事摘要
- 时序事件
- 关键数值
- 技术规格
- 更新记录
- 因果决策
- 用户偏好与约束
- 用户上下文

这一步的意义在于，系统开始具备“先整理记忆，再调用记忆”的能力，而不只是“问一次、检一次”。

### 3. 按题型路由不同记忆视图

V5 的第二个明显增量，是不再对所有问题使用同一套上下文拼装方式，而是按照题型读取不同 section：

- `information_extraction` 重点读取 `Value Registry` 和 `Technical Specifications`
- `knowledge_update` 重点读取关键值、技术规格和更新记录
- `temporal_reasoning` 重点读取时间线和关键值
- `preference_following` 与 `instruction_following` 更依赖用户偏好、因果决策与技术规格
- `multi_session_reasoning` 会同时读取叙事摘要、用户上下文、因果决策、关键值与偏好
- `contradiction_resolution` 重点尝试利用更新/冲突相关记忆
- `event_ordering` 则单独走事件序列上下文，并强制输出编号时间顺序列表

也就是说，V5 已经从“统一 prompt + 统一检索块”的简单范式，演进到“题型感知的上下文装配”。

### 4. 检索结果退居补充证据

在 V5 中，混合检索仍然重要，但它不再是主上下文来源，而是作为结构化记忆之外的补充证据存在。这个变化背后的核心目标，是优先保证回答建立在整理过的稳定记忆之上，减少长文本直接检索带来的噪声和片段化问题。

## 三、结果概览

本节默认采用 `beam_score_vis_merged.json` 中的 `official_avg` 作为主口径，与可视化图 `beam_score_vis.png` 保持一致；`combined_avg` 仅作为辅助参考。

### 1. 总体结果

当前共统计 5 个 case 结果，`official_avg` 平均约为 **61.2%**，`combined_avg` 平均约为 **54.6%**。按 case 看，当前结果如下：

| Split | Case | Official Avg | Combined Avg |
| --- | --- | --- | --- |
| 1M | Case 0 | 51.7% | 49.7% |
| 1M | Case 2 | 65.6% | 56.8% |
| 1M | Case 3 | 61.4% | 59.2% |
| 500K | Case 2 | 58.6% | 43.6% |
| 500K | Case 4 | 68.6% | 63.9% |

从整体表现看：

- 当前最好的 case 是 `500K / Case 4`，官方得分达到 **68.6%**
- 当前相对最弱的是 `1M / Case 0`，官方得分为 **51.7%**
- 即使在较长上下文下，方案也已经能稳定维持在 50% 以上的整体水平，说明“结构化记忆优先”的方向是有效的

### 2. 各题型平均表现

从图表和合并结果看，V5 的题型表现有非常明显的分层：

| Question Type | 平均得分 |
| --- | --- |
| `abstention` | 100.0% |
| `information_extraction` | 95.0% |
| `preference_following` | 85.8% |
| `knowledge_update` | 85.0% |
| `instruction_following` | 70.0% |
| `temporal_reasoning` | 63.3% |
| `summarization` | 49.7% |
| `contradiction_resolution` | 30.4% |
| `multi_session_reasoning` | 29.2% |
| `event_ordering` | 3.3% |

其中可以看到几个非常清晰的结论：

- **强项已经比较明确**：`information_extraction`、`knowledge_update`、`preference_following`、`abstention` 表现稳定，说明结构化记忆对事实保持、更新关系追踪、用户偏好约束和拒答控制是有效的。
- **中间层能力正在形成**：`instruction_following` 和 `temporal_reasoning` 已经达到可用水平，说明题型路由和时间线记忆开始起作用，但稳定性仍有提升空间。
- **短板仍然突出**：`event_ordering`、`contradiction_resolution`、`multi_session_reasoning` 得分明显偏低，表明 V5 目前仍然缺少足够强的跨片段关系建模和严格顺序恢复能力。

### 3. 结果特点解读

从当前结果分布看，V5 更擅长回答“显式事实类问题”，例如版本号、端口、截止日期、配置项、技术栈、用户偏好、更新后的最新值等。这类问题和结构化记忆中的 `Value Registry`、`Technical Specifications`、`User Preferences`、`Update Log` 高度对应，因此表现最稳定。

与之相对，V5 对以下几类问题仍然偏弱：

- **事件排序**：即使已经为 `event_ordering` 单独设计时间线和编号输出格式，当前平均得分仍只有 **3.3%**，说明“有事件列表”并不等于“能稳定恢复与 gold 对齐的事件顺序”。
- **矛盾消解**：当前平均得分 **30.4%**，说明模型往往能提到局部事实，但还不够稳定地完成“显式指出矛盾、列出双方说法、追问哪条为真”这一整套动作。
- **跨 session 归纳**：`multi_session_reasoning` 平均只有 **29.2%**，说明结构化摘要虽然能压缩信息，但对跨多轮、多会话的枚举、计数和全局归纳仍不够稳。
- **长跨度总结**：`summarization` 接近 **49.7%**，属于已经有基础能力，但在跨度大、维度多的工程过程总结中仍容易漏项。

### 4. Case 波动说明

不同 case 间仍然存在较明显波动，这说明方案已经验证方向可行，但稳定性还没有完全打磨到位。

- `500K / Case 4` 表现最完整，说明在局部事实明确、更新关系清晰、时间线较规整的场景下，结构化记忆路线可以释放出较强效果。
- `1M / Case 2` 和 `1M / Case 3` 也已经达到较高水平，说明 V5 并不是只在较短上下文上有效，在 1M 级场景同样具备一定竞争力。
- `1M / Case 0` 和 `500K / Case 2` 的波动则提示我们：一旦问题更依赖跨片段聚合、冲突识别或严格排序，当前方案仍然会出现明显掉分。

因此，V5 当前更适合被描述为“阶段性有效的结构化记忆增强方案”，而不是“已经在所有题型上完成收敛的最终版本”。

## 四、增量工作与阶段进展

如果从研发演进角度总结，V5 本轮最重要的增量工作主要有以下几个方面：

### 1. 从“检索增强”推进到“记忆增强”

此前的 RAG 方案核心是如何改进召回与重排，而 V5 把重点前移到了“如何先把长对话沉淀成一份更可用的记忆”。这代表整个系统开始从单纯的信息召回，转向更接近长期记忆管理的方向。

### 2. 形成了可落盘、可复查的记忆产物

V5 不再把所有中间过程都留在运行时，而是显式生成 `memory.md`、`episodes.jsonl`、`timeline.jsonl`、`memory.json`。这意味着：

- 记忆构建结果可以单独检查
- 题型路由逻辑可以基于固定记忆源复现
- 后续可以围绕具体记忆文件继续迭代排序、冲突消解和聚合策略

这一步对工程化推进很重要，因为它让方案从“黑盒回答”逐步转向“可分析、可调试、可持续优化”的流程。

### 3. 在事实保持与更新追踪上取得了稳定收益

从当前结果看，V5 已经明显增强了以下能力：

- 对显式事实的提取能力
- 对最新值和更新关系的保持能力
- 对用户偏好与约束的遵循能力
- 在信息不足时避免乱答的能力

这些结果说明，结构化记忆层并不是形式上的改造，而是已经对官方评分中的多个关键题型产生了实质帮助。

### 4. 问题边界被进一步收敛

V5 的价值不仅在于“做对了什么”，也在于“更清楚地暴露了剩余难点是什么”。经过这一轮实验，后续优化重点已经更集中地收敛到三类核心问题：

- V5版本在 **事件排序** 上的百分比评分较前四个版本实现零的突破，但事件排序表示仍然薄弱
- 矛盾信息的显式建模仍然不足
- 多 session 信息的跨片段聚合仍然不稳定

这比继续泛泛地优化检索 Top-K 更有方向性，因为当前瓶颈已经不再只是“能不能找回来”，而是“找回来以后能不能正确组织并推理”。

## 五、阶段结论与下一步方向

综合当前实现和评测结果，可以把 V5 的阶段结论概括为：

**RAG V5 已经完成了从纯检索增强到题型感知记忆增强的关键过渡。**

它已经证明了一件重要的事：在超长上下文任务中，先把长对话整理成结构化记忆，再按题型读取不同记忆片段，是一条真实有效的方向。尤其在信息提取、知识更新、偏好跟随和拒答控制上，V5 已经表现出较强稳定性。

但与此同时，V5 也清楚暴露出当前路线的上限所在：仅仅把事实、偏好和更新时间整理出来，还不足以自动解决事件顺序恢复、矛盾识别和跨会话全局归纳。这意味着后续工作重点不应只是继续堆召回和重排，而应进一步加强：

- 面向 `event_ordering` 的排序表示与事件粒度对齐
- 面向 `contradiction_resolution` 的冲突显式建模
- 面向 `multi_session_reasoning` 的跨 session 聚合与全局汇总机制

总体而言，V5 已经把项目重点从“是否应该做 RAG”推进到了“如何把 RAG 做成可路由、可复用、可持续优化的记忆系统”。这一步本身就是明确的增量工作和阶段进展，也为后续继续推进融合式长期记忆方案打下了更扎实的基础。
